## SQ1: What does Blattomat (~/Code/blattwerk) do and how: page and block model, canvas code, ProseMirror text, undo, how the agent edits through MCP, and what licenses its dependencies carry?

### What it is

- Blattomat is "A worksheet editor for Grundschule teachers: an A4 canvas like PowerPoint, with blocks made for school sheets, a maths generator with exact limits, and a PDF that matches the screen" [source: /home/pascal/Code/blattwerk/docs/spec-v0.md:1-3 | Blattomat v0 spec | practitioner].
- Its v0 test is one teacher rebuilding one real sheet on the iPad and printing it [source: /home/pascal/Code/blattwerk/docs/spec-v0.md "The test" | Blattomat v0 spec | practitioner]. The decks spec copies this shape of test ("one existing deck ... rebuilt in decks") [source: /home/pascal/Code/.worktrees/decks/research/docs/spec-v0.md "The test" | decks v0 spec | practitioner].

### Page and block model

- A sheet is a `doc`: `{"pages": [{"blocks": []}], "guides": {"x": [], "y": []}, "grid": 0}` [source: /home/pascal/Code/blattwerk/docs/okf/page-model.md "Page model" | OKF page model | practitioner].
- Every length is mm from the paper's top left; there is "no unit field and no pixel"; font sizes are pt [source: /home/pascal/Code/blattwerk/docs/okf/page-model.md "The paper"; /home/pascal/Code/blattwerk/docs/okf/mm-and-pt.md | OKF mm and pt | practitioner].
- Every block has the same box fields: `id`, `type`, `x`, `y`, `w`, `h`, `z`, `locked`, `props` [source: /home/pascal/Code/blattwerk/docs/okf/page-model.md "The box of a block" | OKF page model | practitioner]. The generated reference adds optional box fields `mark`, `group` (list of group ids, outermost first), `angle`, `flipX`, `flipY`, `keep` (aspect lock) [source: /home/pascal/Code/blattwerk/docs/okf/blocks/text.md "Block fields" | OKF block text | practitioner].
- Pages carry no id. `pages` is "in print order", and the tools address a page by 1-based number (`page` argument of `add_block`, `add_page` `after`) [source: /home/pascal/Code/blattwerk/docs/okf/page-model.md "Pages"; /home/pascal/Code/blattwerk/docs/okf/tools/errors-and-limits.md "add_block", "add_page" | OKF tools errors and limits | practitioner]. The JSON Schema `Page` definition holds `blocks`, `guides`, `grid` and no `id` [source: /home/pascal/Code/blattwerk/src/blattwerk/sheet.schema.json:83-98 | sheet schema | practitioner].
- Block ids are `crypto.randomUUID()` both in the editor and in the MCP server's `add_block` [source: /home/pascal/Code/blattwerk/frontend/src/pages/Editor.tsx `add` (about line 2705); /home/pascal/Code/blattwerk/frontend/mcp/tools.ts:265 | Editor and MCP tools | practitioner].
- Rich text: a text block keeps plain `props.text`, and once part of it has its own look, `props.rich` holds paragraphs of runs (`bold`, `italic`, `underline`, `color`) with `list` (`bullet` or `number`) and `level` 0 to 2. "The page draws `rich` as text in elements of its own making, never as stored markup, so a sheet cannot bring script into the page Chromium prints" [source: /home/pascal/Code/blattwerk/docs/spec-v0.md "Sheet document" | Blattomat v0 spec | practitioner].
- Table props: `cells` (rows of strings), `cols` (column shares), no stored row height; rows grow with text [source: /home/pascal/Code/blattwerk/docs/spec-v0.md "Sheet document" | Blattomat v0 spec | practitioner].
- The schema is generated from the TypeScript types in `src/sheet.tsx` by `ts-json-schema-generator`, with `additionalProperties: true` so "a tab opened before a deploy, or a sheet a later build wrote, must still save"; `--check` fails lint when the file drifts or a field lacks a description [source: /home/pascal/Code/blattwerk/frontend/schema.mjs:1-12 | schema generator | practitioner]. The server checks every saved document against it with `jsonschema` Draft 7 and turns errors into plain words [source: /home/pascal/Code/blattwerk/src/blattwerk/schema.py:1-20 | schema check | practitioner].
- The block set grew to 27 types kept for the MCP server (text, shape, ruling, name, points, symbol, image, maths, table and 18 maths/word exercise types) [source: /home/pascal/Code/blattwerk/frontend/mcp/tools.ts:17-18 `KEPT_BLOCKS` | MCP tools | practitioner].

### ProseMirror text field

- "ProseMirror, for the one text being edited; every other text draws without it ... it is the smallest of the libraries tried and has no history of its own, so undo stays the editor's" [source: /home/pascal/Code/blattwerk/docs/spec-v0.md "Architecture" | Blattomat v0 spec | practitioner].
- Field.tsx: "The field a text is typed in: ProseMirror, with a document as flat as the sheet's own paragraphs. Only the editor loads it; the sheet draws without it." ### Undo

- Undo is whole-document snapshots: `type Step = { doc: Doc; from: number; to: number }; type Hist = { past: Step[]; doc: Doc; future: Step[] }` [source: /home/pascal/Code/blattwerk/frontend/src/history.ts:4-6 | history.ts | practitioner].
- Changes that share a gesture key merge into one step; "A change that leaves the sheet as it is makes nothing: no step, and redo stays"; a gesture that comes back to its start removes its step [source: /home/pascal/Code/blattwerk/frontend/src/history.ts `changed` | history.ts | practitioner].
- History lives in the `Canvas` component state: `useState<Hist>(() => ({ past: [], doc: file.doc, future: [] }))` [source: /home/pascal/Code/blattwerk/frontend/src/pages/Editor.tsx:414 | Editor | practitioner]. When a newer sheet is loaded, `renew` bumps a counter used as the React `key` of `Canvas` (`<Canvas key={file.n} ...>`), which mounts a new Canvas and so starts a new, empty history [source: /home/pascal/Code/blattwerk/frontend/src/pages/Editor.tsx:388, 402 | Editor renew | practitioner]. ### How the agent edits through MCP

- Two transports, one tool set: an MCP server over stdio (Claude Desktop extension `.mcpb`) and a remote route `/mcp` [source: /home/pascal/Code/blattwerk `git log` e8af3b5 "an MCP server over stdio with coarse tools", 51d2670 "a Claude Desktop extension (.mcpb)", 0b4598d "the remote MCP connector at /mcp with its own OAuth sign-in" | git log | practitioner].
- The remote route: FastAPI checks the bearer token (only OAuth tokens starting `bo_`, not API keys), then forwards the JSON-RPC body to a Node child process (`frontend/mcp/http.ts`) that "runs the same tools as stdio"; GET and DELETE answer 405 [source: /home/pascal/Code/blattwerk/src/blattwerk/remote.py:1-117 | remote.py | practitioner].
- OAuth 2.1 in `oauth.py`: PKCE (43 to 128 unreserved characters), code lifetime 300 s, access token 3600 s, refresh 90 days, dynamic client registration, https redirect URIs or http on loopback only [source: /home/pascal/Code/blattwerk/src/blattwerk/oauth.py:1-60 | oauth.py | practitioner].
- Tools (16): `list_sheets`, `get_sheet`, `create_sheet`, `rename_sheet`, `duplicate_sheet`, `replace_doc`, `add_block`, `update_block`, `move_block`, `delete_block`, `add_page`, `set_page`, `set_words`, `upload_picture`, `send_feedback`, `render_preview` [source: /home/pascal/Code/blattwerk/frontend/mcp/tools.ts:442-629 | MCP tool definitions | practitioner].

### Versions and the 409 rule

- "Every sheet has a `version`. `get_sheet` gives it. Every write takes the version you have and answers the new one." "Only a write of the doc moves the version on. `rename_sheet` changes the title and leaves the version as it is." [source: /home/pascal/Code/blattwerk/docs/okf/versions.md | OKF Versions and the 409 rule | practitioner]
- Server side: the save is one SQL `UPDATE ... SET version = version + (?2 IS NOT NULL) ... WHERE id = ?3 AND user_id = ?4 AND (?2 IS NULL OR version = ?5)`, so a doc write lands only when the stored version equals the one sent [source: /home/pascal/Code/blattwerk/src/blattwerk/sheets.py:117-135 | sheets.py save | practitioner]. A doc write without a version is refused: "a doc needs the version it was based on" [source: /home/pascal/Code/blattwerk/src/blattwerk/sheets.py:28-34 | sheets.py Change | practitioner].
- Fine tools refuse on a stale version with the exact text "The teacher changed this sheet in the editor since you read it (you had version <had>, it is now <now>). Nothing was written. Call get_sheet and make your change on the new doc." [source: /home/pascal/Code/blattwerk/frontend/mcp/tools.ts:121-122; /home/pascal/Code/blattwerk/docs/okf/tools/errors-and-limits.md | MCP stale text | practitioner]
- `replace_doc` retries once with the new version only when "the version moved, the content did not" (the doc on the server is still the one this session last read or wrote) [source: /home/pascal/Code/blattwerk/docs/okf/versions.md "replace_doc" | OKF versions | practitioner].
- The agent docs explain why: "The editor saves itself ... So she can change a sheet while you work on it. The version can move between your `get_sheet` and your write, at any time." and "Never write an old doc back over the teacher's change." [source: /home/pascal/Code/blattwerk/docs/okf/versions.md "Why it happens", "What to do" | OKF versions | practitioner]

### The editor side: saver, clash, no push

- The editor saves 2 s after a change (`AFTER = 2000`) [source: /home/pascal/Code/blattwerk/frontend/src/saves.ts:5-6 | saves.ts | practitioner].
- Each sheet has one `Saver` that outlives the editor, with `base` (the version every save is based on), `saved`, `want`, `out`, `lost`, and a `clash` flag: "The server holds another device's document: saving stops until the teacher has chosen." [source: /home/pascal/Code/blattwerk/frontend/src/saves.ts:9-60 | saves.ts Saver | practitioner]
- In a clash the teacher chooses between the other version and overwrite (`overwrite`, `keepAsNew`, `discard` exports) [source: /home/pascal/Code/blattwerk/frontend/src/saves.ts:389-425 | saves.ts clash choice | practitioner].
- No server push: `saves.ts` and `api.ts` contain no `EventSource`, `WebSocket` or `setInterval` (grep). An open editor learns of a newer version only (a) on the window `focus` event, which calls `newerSheet`, and (b) on the cross-tab `storage` event that `announceSaved` fires from another tab of the same browser [source: /home/pascal/Code/blattwerk/frontend/src/pages/Editor.tsx:484-489; /home/pascal/Code/blattwerk/frontend/src/saves.ts:445-476 | Editor focus handler and saves.ts newer() | practitioner]. `newer()` loads the server's sheet only when the window has no unsaved change of its own [source: /home/pascal/Code/blattwerk/frontend/src/saves.ts:460-476 | saves.ts newer() | practitioner].
- Git history on this area: "a quiet window loads the newer sheet before it prints ... one clash bar" (#726), "a clash stands through every reload, a kept change goes only with its owner" (#352), "the PDF waits in a clash" (#710) [source: /home/pascal/Code/blattwerk `git log` b05ea6f, 3567ffb, e44ac3d | git log | practitioner].
- Granularity: every write (editor or agent) sends the whole document; there are no per-block operations on the wire (`PATCH /sheets/<id>` with `{doc, version}`) [source: /home/pascal/Code/blattwerk/frontend/mcp/tools.ts:129; /home/pascal/Code/blattwerk/src/blattwerk/sheets.py:117-135 | MCP edit and server save | practitioner].
- Ids: blocks have UUIDs; pages are addressed by position (see SQ1) [source: /home/pascal/Code/blattwerk/frontend/mcp/tools.ts:265; /home/pascal/Code/blattwerk/docs/okf/page-model.md "Pages" | MCP and page model | practitioner]. Selbstkontrolle blocks reference other blocks by id in `links` [source: /home/pascal/Code/blattwerk/docs/okf/server-computes.md "Selbstkontrolle" | OKF server-computes | practitioner].
