## SQ1: How does PresentationML model animations and transitions?

### Overall structure of `p:timing`

All of a slide's animation lives in one `p:timing` element. python-pptx models `p:sld` children in the fixed order `("p:cSld", "p:clrMapOvr", "p:transition", "p:timing", "p:extLst")` and `p:timing` children as `("p:tnLst", "p:bldLst", "p:extLst")` [source: https://github.com/scanny/python-pptx/blob/master/src/pptx/oxml/slide.py | python-pptx `oxml/slide.py` (CT_Slide, CT_SlideTiming) | vendor].

The spec's own skeleton for the root: `<p:timing><p:tnLst><p:par><p:cTn id="1" dur="indefinite" restart="never" nodeType="tmRoot"><p:childTnLst><p:seq concurrent="1" nextAc="seek">…</p:seq></p:childTnLst></p:cTn></p:par></p:tnLst></p:timing>` [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/seq.html | ECMA-376 Part 1, seq (Sequence Time Node), §4.6.65 | independent].

`p:seq` "describes the Sequence time node and it can only be activated when the one before it finishes." Attributes: `concurrent` ("the previous element is left enabled when advancing to the next element"), `nextAc` ("When this is set to seek it will seek the element to a natural end time"), `prevAc` ("what to do when going backwards in a sequence … When the value is "skipTimed", the sequence will continue to go backwards until it reaches a sequence element that was defined to begin only on the next condition element") [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/seq.html | ECMA-376 seq | independent]. `ST_TLPreviousActionType` has only `none` and `skipTimed` [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/ST_TLPreviousActionType.html | ECMA-376 ST_TLPreviousActionType | independent].

Node types (`cTn@nodeType`, `ST_TLTimeNodeType`): `clickEffect`, `withEffect`, `afterEffect`, `mainSeq`, `interactiveSeq`, `clickPar`, `withGroup`, `afterGroup`, `tmRoot` [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/ST_TLTimeNodeType.html | ECMA-376 ST_TLTimeNodeType | independent].

Preset classes (`cTn@presetClass`, `ST_TLTimeNodePresetClassType`): `entr` (Entrance), `exit`, `emph` (Emphasis), `path`, `verb`, `mediacall` [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/ST_TLTimeNodePresetClassType.html | ECMA-376 ST_TLTimeNodePresetClassType | independent].

`cTn` attributes relevant to the spec's model, quoted from the reference: `presetID` ("the preset identifier for the time node", xsd:int, no enumeration in the standard); `presetSubtype` ("a bitflag that specifies a direction or some other attribute of the effect. For example it can be set to specify a "From Bottom" for the Fly In effect"); `dur` (ST_TLTime); `accel`/`decel` (percentage of duration to accelerate/decelerate); `autoRev`; `repeatCount` ("in units of thousandths", default `1000`); `spd` ("If negative, the timing will be reversed"); `fill`; `grpId`; `bldLvl`; `afterEffect`; `nodeType` [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/cTn.html | ECMA-376 cTn (Common Time Node Properties), §4.6.33 | independent]. The standard does not list which `presetID` numbers mean which effect (no enumeration in the schema fragment; type is plain `xsd:int`) [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/cTn.html | ECMA-376 cTn (Common Time Node Properties), §4.6.33 | independent].

Start conditions: `stCondLst` holds `cond` elements; the spec example "a shape with an entrance appearance after 5 seconds" is `<p:cTn id="5" nodeType="clickEffect"><p:stCondLst><p:cond delay="5000"/></p:stCondLst>` [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/stCondLst.html | ECMA-376 stCondLst | independent]. `cond` carries `delay` (ST_TLTime) and `evt` (ST_TLTriggerEvent) and may target `tgtEl`, `tn` or `rtn` [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/cond.html | ECMA-376 cond | independent].

### A real PowerPoint-saved effect (Fly In, from bottom, on click)

Sample: `file_with_bounce.pptx`, attached to python-pptx issue #954; its `docProps/app.xml` reads `<Application>Microsoft Macintosh PowerPoint</Application>` `<AppVersion>16.0000</AppVersion>` [source: https://github.com/scanny/python-pptx/files/14556139/file_with_bounce.pptx | PowerPoint-saved sample attached to python-pptx #954 | practitioner]. Observed structure in `ppt/slides/slide1.xml` (read locally after download):

- `p:timing` sits inside `<mc:AlternateContent>` with `<mc:Choice Requires="p14">` (carrying `p14:presetBounceEnd="50000"` and `p14:bounceEnd`) and an `<mc:Fallback>` copy of the same timing without the p14 attributes.
- Nesting under `mainSeq`: an outer `p:par` whose `cTn fill="hold"` has `<p:cond delay="indefinite"/>` (the click), then an inner `p:par` with `<p:cond delay="0"/>`, then the effect `p:par` with `<p:cTn id="5" presetID="2" presetClass="entr" presetSubtype="4" fill="hold" grpId="0" nodeType="clickEffect">`.
- The effect's children: a `p:set` of `style.visibility` to `visible` with `dur="1"`, then two `p:anim calcmode="lin" valueType="num"` on `ppt_x` (`#ppt_x` → `#ppt_x`) and `ppt_y` (`1+#ppt_h/2` → `#ppt_y`), each `dur="500"`; targets are `<p:spTgt spid="4"/>`.
- After the `mainSeq` `cTn`: `<p:prevCondLst><p:cond evt="onPrev" delay="0"><p:tgtEl><p:sldTgt/></p:tgtEl></p:cond></p:prevCondLst>` and the matching `nextCondLst` with `evt="onNext"`.
- `<p:bldLst><p:bldP spid="4" grpId="0"/></p:bldLst>` links the shape to the effect's `grpId`.

Corroboration of the three-level click-group nesting from a library that says it derived its templates "from real PowerPoint-exported PPTX files (fixed reference XMLs)": outer click-group `p:par` with `delay="indefinite"`, inner wrapper with `delay="0 or cumulative ms"`, then `clickEffect` and `withEffect` siblings, and "a separate inner wrapper for each afterEffect"; "prevCondLst / nextCondLst MUST target <p:sldTgt/> for numbered animations"; "bldLst entries MUST include animBg="1"" [source: https://github.com/atharva9167j/dom-to-pptx/blob/master/src/animations/xml-templates.js | dom-to-pptx `xml-templates.js` header comment | vendor]. Note: the PowerPoint-saved sample above has `<p:bldP spid="4" grpId="0"/>` with no `animBg` attribute, which does not match the "MUST include animBg" rule in dom-to-pptx's comment (contradiction) [source: https://github.com/scanny/python-pptx/files/14556139/file_with_bounce.pptx | PowerPoint-saved sample attached to python-pptx #954 | practitioner; https://github.com/atharva9167j/dom-to-pptx/blob/master/src/animations/xml-templates.js | dom-to-pptx `xml-templates.js` | vendor].

Entrance/exit ordering rule from the same file: "ENTRANCE animations: 1. <p:set style.visibility="visible"> FIRST (delay=0) 2. Then the actual effect"; "EXIT animations: 1. The actual effect FIRST 2. Then <p:set style.visibility="hidden"> at the END (delay=duration-1)" [source: https://github.com/atharva9167j/dom-to-pptx/blob/master/src/animations/xml-templates.js | dom-to-pptx | vendor].

### Behaviour elements

- `animEffect`: "image transform/filter effects"; `transition` = `in` | `out` | `none`; `filter` syntax `"type(subtype);type(subtype)"`, e.g. `filter="blinds(horizontal)"`; the runtime tries filters left to right "until it either finds one it supports" [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/animEffect.html | ECMA-376 animEffect | independent]. The `tgtEl` example applies `<p:animEffect transition="in" filter="fade">` to `spid="3"` [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/tgtEl.html | ECMA-376 tgtEl | independent].
- `animScale`: example "emphasize a shape by scaling it larger by 150%" with `<p:by x="150000" y="150000"/>`; attribute `zoomContents` [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/animScale.html | ECMA-376 animScale | independent].
- `animClr`: example changes `fillcolor` to `<a:schemeClr val="accent2"/>`; `clrSpc` RGB or HSL ("The RGB color space is best used for doing animations between two different colors") [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/animClr.html | ECMA-376 animClr | independent].
- `animMotion`: "the ability to specify from/to/by type motion as well as to use more detailed path descriptions for motion over polylines or bezier curves". Example: `<p:animMotion origin="layout" path="M 0 0 L 0.25 0 E" pathEditMode="relative">` animating `ppt_x`/`ppt_y`. Path syntax quoted: "M = move to, L = line to, C = curve to, Z=close loop, E=end; UPPERCASE = absolute coords, lowercase = relative coords. Thus total allowed set = {M,L,C,Z,E,m,l,c,z,e}"; sample `"M 0 0 L 1 1 c 1 2 3 4 4 4 Z"`. `ptsTypes`: "A = Auto, F = Corner, T = Straight, S = Smooth". Also `rAng`, `rCtr`, `origin` (`parent` | `layout`), `pathEditMode` (`relative` | `fixed`) [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/animMotion.html | ECMA-376 animMotion | independent; https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/ST_TLAnimateMotionPathEditMode.html | ECMA-376 ST_TLAnimateMotionPathEditMode | independent; https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/ST_TLAnimateMotionBehaviorOrigin.html | ECMA-376 ST_TLAnimateMotionBehaviorOrigin | independent].
- Note on path coordinates: the spec example moves a shape right by `0.25`; the reference page does not define the unit in the text quoted above. Path syntax letters (M, L, C, Z) overlap with SVG path data, but `E` (end) and the absence of SVG's H, V, S, Q, T, A commands differ [author estimate: comparison of the ECMA letter set above against the SVG path command set; no source compares them directly].

### Builds by paragraph (`p:bldLst`, `p:bldP`, `p:txEl`)

- `bldP` "specifies how to build paragraph level properties"; example "animation applied only to 1st level paragraphs": `<p:bldLst><p:bldP spid="3" grpId="0" build="p"/></p:bldLst>`. Attributes: `build` (default `whole`), `bldLvl` (default 1, "only supported in paragraph type builds"), `animBg`, `autoUpdateAnimBg`, `rev` (last paragraph animates first), `advAuto` (default `indefinite`), `grpId` ("ties effects persisted in the animation to the build information … GroupIDs are unique for a given shape. They are not guaranteed to be unique IDs across all shapes on a slide"), `spid`, `uiExpand` [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/bldP.html | ECMA-376 bldP | independent].
- `ST_TLParaBuildType`: `allAtOnce`, `cust` ("custom user settings"), `p` ("animate paragraphs grouped by bullet level"), `whole` ("animate the entire body of text as one block") [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/ST_TLParaBuildType.html | ECMA-376 ST_TLParaBuildType | independent].
- Per-paragraph targets: `<p:tgtEl><p:spTgt spid="5"><p:txEl><p:pRg st="1" end="1"/></p:txEl></p:spTgt></p:tgtEl>`; `txEl` takes either `charRg` or `pRg` [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/txEl.html | ECMA-376 txEl | independent].
- A library that writes per-paragraph targets emits exactly `<p:tgtEl><p:spTgt spid="${spid}"><p:txEl><p:pRg st="${paragraphIndex}" end="${paragraphIndex}"/></p:txEl></p:spTgt></p:tgtEl>` when `build === 'paragraph'` [source: https://github.com/atharva9167j/dom-to-pptx/blob/master/src/animations/xml-templates.js | dom-to-pptx | vendor].
- Gap: no PowerPoint-saved sample of a `build="p"` text build was obtained in this round (GitHub code search returned schema files and third-party generators, not PowerPoint output). The ECMA examples and the dom-to-pptx template stand in for it.
- Chart targets differ: OfficeCLI's code comments "chart targets get <p:bldGraphic>, not <p:bldP>" [source: https://github.com/iOfficeAI/OfficeCLI/blob/main/src/officecli/Handlers/Pptx/PowerPointHandler.Animations.cs | OfficeCLI `PowerPointHandler.Animations.cs` | vendor].
- A hazard noted by an SVG→pptx converter: "`<p:bldP>` entries must carry `grpId` matching the animation `<p:cTn>` group. Mismatched `grpId` causes silent failure" [source: https://github.com/BramAlkema/svg2ooxml/blob/main/docs/specs/animation-fidelity.md | svg2ooxml "Animation Fidelity Specification" (Draft, 2026-03-25, section 5 added 2026-04-17) | practitioner].

### Transitions (`p:transition`) and extensions

- `p:transition` is stored "on the slide that will appear after the transition is complete"; parents are `sld`, `sldLayout` and `sldMaster`. Choices in ECMA-376 include `blinds, checker, circle, comb, cover, cut, diamond, dissolve, fade, newsflash, plus, pull, push, random, randomBar, split, strips, wedge, wheel, wipe, zoom`. Attributes: `spd` (ST_TransitionSpeed, default `fast`), `advClick` (default true), `advTm` (ms) [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/transition.html | ECMA-376 transition | independent]. All five spec transitions (none, fade, push, wipe, zoom) exist in this list; `none` corresponds to no element or `cut` [author estimate: spec-v0.md §4 list compared with the ECMA choice list].
- The ECMA `p:transition` has only `spd` (a speed keyword), not a duration in ms [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/transition.html | ECMA-376 transition | independent]. A millisecond duration is written as `p14:dur` (namespace `http://schemas.microsoft.com/office/powerpoint/2010/main`) inside an `mc:AlternateContent` `mc:Choice`; OfficeCLI documents "DUR: integer in ms (e.g. 1000)", noting it "requires Office 2010+" and its `InsertTransitionWithMcWrapper` emits "mc:AlternateContent > mc:Choice[Requires=nsPrefix] > p:transition > child" plus "mc:Fallback > p:transition > p:fade (graceful degradation for older PPT)" [source: https://github.com/iOfficeAI/OfficeCLI/blob/main/src/officecli/Handlers/Pptx/PowerPointHandler.Animations.cs | OfficeCLI | vendor].
- python-pptx issue #1106 (2026-01-20): transitions worked "only … by manually injecting XML (using mc:AlternateContent) based on known examples … it feels fragile" [source: https://github.com/scanny/python-pptx/issues/1106 | python-pptx #1106 | practitioner].
- Morph: namespace `http://schemas.microsoft.com/office/powerpoint/2015/09/main`, element `p159:morph` with `option` = `byObject` | `byWord` | `byChar`; OfficeCLI says "Morph transition: requires mc:AlternateContent wrapper with p159 namespace" [source: https://github.com/iOfficeAI/OfficeCLI/blob/main/src/officecli/Handlers/Pptx/PowerPointHandler.Animations.cs | OfficeCLI | vendor]. Microsoft's Resource2Skill writes the same element without the wrapper: `<p:transition … xmlns:p159="…/2015/09/main" spd="med" advClick="1"><p159:morph option="byObject"/></p:transition>` [source: https://github.com/microsoft/Resource2Skill/blob/main/domains/ppt/mcp_server/server.py | Resource2Skill | vendor]. The two writers differ on the wrapper; the [MS-PPTX] spec that would settle it was [inaccessible].
- Morph option meanings: byObject "considering shapes as indivisible objects"; byWord "transferring text by words where possible"; byChar "by characters where possible" [source: https://apireference.aspose.com/slides/java/com.aspose.slides/transitionmorphtype | Aspose TransitionMorphType | vendor (read via search excerpt)].
- Morph matching (Microsoft): name an object starting with "!!" on both slides; "won't match a "!!" object with a non-"!!" object"; expects "a 1:1 mapping"; same-type objects morph (shapes, images, tables, SmartArt); charts cross-fade instead. Creation support from PowerPoint for Microsoft 365 Windows 1903, Mac 16.23, PowerPoint 2019 1908; PowerPoint 2016 for Windows can play but not create [source: https://support.microsoft.com/en-us/office/morph-transition-tips-and-tricks-bc7f48ff-f152-4ee8-9081-d3121788024f | Morph transition: Tips and tricks | vendor].
- Non-standard features move the whole `p:timing` into `mc:AlternateContent`: "When a non-openxml feature is used in animations, Powerpoint wraps the `<p:timing>` element in a `<mc:AlternateContent>`. ### reveal.js (6.0.2, repository HEAD 2026-09-30)

## SQ4: How do web runtimes play steps, handle going backwards, and animate SVG internals?

### Web Animations API

- `Animation.reverse()` "reverses the playback direction, meaning the animation ends at its beginning"; "If called on an unplayed animation, the whole animation is played backwards"; "If called on a paused animation, the animation will continue in reverse" [source: https://developer.mozilla.org/en-US/docs/Web/API/Animation/reverse | MDN Animation.reverse() | independent].
- "`Animation.reverse()` sets the animation's playback rate … to a negative value so it runs backward"; use `updatePlaybackRate()` for smooth changes; `currentTime` can be set directly; "`Animation.finish()` skips to the end"; "`Animation.cancel()` aborts the animation and removes its effects"; a `finished` promise; MDN advises against relying on fill modes to persist end state because animation styles have higher cascade precedence, and recommends `commitStyles()`, which "writes the computed values of the animation's current styles into its target element's `style` attribute"; "The `animate()` method can be called on any DOM element that could be animated with CSS" [source: https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API/Using_the_Web_Animations_API | MDN Using the Web Animations API | independent].
- Motion along a path: `offset-path: path("…")` takes SVG path data; `offset-distance` 0% to 100% moves along it; `offset-rotate`; reference box options; "Baseline: Widely available … since March 2022" [source: https://developer.mozilla.org/en-US/docs/Web/CSS/offset-path | MDN offset-path | independent].

### reveal.js stepping and going back

- `navigatePrev()`: "Prioritize revealing fragments": it calls `fragments.prev()` first and moves to the previous slide only when that returns false [source: https://github.com/hakimel/reveal.js/blob/master/js/reveal.js | reveal.js `js/reveal.js` navigatePrev | vendor].
- Slides before the current one get all fragments shown ("Show all fragments in prior slides"), slides after get them hidden ("Hide all fragments in future slides") [source: https://github.com/hakimel/reveal.js/blob/master/js/reveal.js | reveal.js updateSlides | vendor]. Visibility is a function of the index: stepping back removes `visible` from fragments above the index and fires `fragmenthidden` [source: https://github.com/hakimel/reveal.js/blob/master/js/controllers/fragments.js | reveal.js fragments.js | vendor]. The revealjs.com fragments page does not describe backward behaviour [source: https://revealjs.com/fragments/ | reveal.js Fragments | vendor].

### Slidev stepping and going back

- `next()` sets `clicksDirection = 1` and increments `queryClicks` until `clicksTotal`, then `nextSlide()`; `prev()` sets `clicksDirection = -1`, decrements `queryClicks`, and at the first click calls `prevSlide(true)`, which goes to the previous slide with `CLICKS_MAX` (all its clicks done) unless printing [source: https://github.com/slidevjs/slidev/blob/main/packages/client/composables/useNav.ts | Slidev `useNav.ts` | vendor].
- Element state is derived from `$clicks` ranges (`v-click`, `click-x-y` motion variants), and hiding is a CSS class with a CSS transition [source: https://github.com/slidevjs/slidev/blob/main/docs/guide/animations.md | Slidev Animation guide | vendor].

### PowerPoint and LibreOffice going back

- PowerPoint returning to an already-played slide: "PowerPoint remembers that you've been there, done that, so it shows you the slide as it was in its final state"; workaround: a blank auto-advancing helper slide before it [source: https://www.rdpslides.com/pptfaq/FAQ00598_Animations_don-t_play_when_I_go_back_to_a_slide.htm | PPT FAQ: Animations don't play when I go back to a slide | practitioner].
- No Microsoft source was found on what the back arrow does to an individual animation step within a slide (gap). The file format carries the hooks: `seq@prevAc` and `prevCondLst` with `evt="onPrev"` [source: https://webapp.docx4java.org/OnlineDemo/ecma376/PresentationML/seq.html | ECMA-376 seq | independent; https://github.com/scanny/python-pptx/files/14556139/file_with_bounce.pptx | PowerPoint-saved sample attached to python-pptx #954 | practitioner].
- Transitions backward: a 2020 comment on LibreOffice bug 34407 quotes a Microsoft forum answer, "This is no longer necessary with PowerPoint 2010. All the transitions support backward/forward appropriately"; a 2013 comment attached videos comparing Office 2013 (reversed) with LibreOffice 4.0 (not reversed); the bug (opened 2011-02-17) is still NEW [source: https://bugs.documentfoundation.org/show_bug.cgi?id=34407 | LibreOffice Bug 34407 | independent]. A 2012 comment in the same bug raises objections: quick backward scrolling slowed by effects, symmetric effects, quizzes, and sound/video [source: https://bugs.documentfoundation.org/show_bug.cgi?id=34407 | LibreOffice Bug 34407 | independent].

### Animating SVG internals by selector in HTML decks

- reveal.js with inline SVG: "Adding `class="fragment"` (and variations...) to the SVG elements helps animate parts of the diagram", with `data-fragment-index` for order; the SVG must be embedded in the HTML, not referenced as an image (2019-11-26) [source: https://www-public.telecom-sudparis.eu/~berger_o/weblog/tag/svg/index.html | Displaying animated diagrams in org-reveal slide decks with SVG (Olivier Berger) | practitioner].
- Sacha Chua (2024-01): IDs on SVG paths, the full SVG inlined "instead of just including it with an img tag", generated CSS dims non-current parts to 0.2 opacity and uses staggered transition delays; she calls the result "very messy CSS" [source: https://sachachua.com/blog/2024/01/animating-svg-topic-maps-with-inkscape-emacs-ffmpeg-and-reveal-js/ | Animating SVG topic maps with Inkscape, Emacs, FFmpeg, and Reveal.js | practitioner].
- A reveal.js "animate" plugin drives SVG with SVG.js, configured as an array per fragment step [source: https://people.willamette.edu/~jjrembold/class_files/data275/Slides/html_srcs/plugin/animate/README.md | reveal.js animate plugin README | practitioner (read via search excerpt)].
- dom-to-pptx previews its pptx animations in the browser with a CSS stylesheet and `applyBrowserAnimations(parentElement, { enableClick })`, which "accurately calculates the staggered duration of paragraph and letter builds"; "slide-to-slide transitions are not previewed in the browser" [source: https://github.com/atharva9167j/dom-to-pptx | dom-to-pptx README | vendor].
